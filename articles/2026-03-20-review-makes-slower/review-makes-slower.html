Every layer of review makes you 10x slower

Avery Pennarun 的效率哲学：审查层如何拖慢你

📅 2026-03-20 ⏱️ 阅读时间: 5分钟 🏷️ 效率方法 / 工程文化 / Avery Pennarun

10x 规律

写代码修 bug 30 分钟
同事 code review 5 小时
架构师审批设计文档 1 周
跨团队协调 1 季度
几乎所有的额外时间都花在 等待 上

为什么不能直接删掉审核？

🤖 AI 解决不了这个问题

AI 写代码快，但 review 还是慢

• AI 写代码快，但 review 还是慢

• 不读代码就提交 = 制造更多问题

⚠️ 多层 QA 反而降低质量

• 第一层：反正有第二层，不用太仔细

• 开发者：有 QA 帮我查，不用太小心

• 结果：每层都推诿，质量反而下降

🤝 真正的问题是信任

🇯🇵 日本工厂：没有 QA，但有"停线按钮"

🇺🇸 美国学样：装了按钮，没人敢按

区别：日本工人知道停线不会被骂

解决方案

❌ 错误做法

  • 增加审核层抓 bug
  • 多层 QA 互相检查
  • 靠流程保证质量

✅ 正确做法

  • 用工程消灭整类问题
  • 建立信任文化
  • 让审核变得不再需要

gofmt 的启示

Code review 的目标不是抓 bug，而是

消灭整类 review comment

gofmt 消灭了所有关于空格的 review comment
这才是工程

审核层的存在是因为质量不够
目标是让审核变得不再需要
而不是增加更多审核

核心启示

质量从下往上生长

不是从上往下审查

小团队 → 清晰接口 → 相互信任
每个人对自己的模块负责
